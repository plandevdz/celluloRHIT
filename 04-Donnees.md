# Dictionnaire logique et règles d’intégrité | v2
Contrat pour le développeur : matérialiser les relations par clés étrangères. Chaque table métier a un id interne et les horodatages utiles. Les données variables sont normalisées ; les snapshots à une date et les preuves signées sont immuables. Un champ inconnu reste NULL. Les noms SQL ci-dessous sont proposés ; les notions et les contraintes sont obligatoires.

| Table (une ligne représente…) | Données et liens essentiels | Contrainte / propriétaire |
|---|---|---|
| users, roles, user_roles | Utilisateur nominatif, email, équipe/site facultatif, actif ; couple utilisateur-rôle | Exactement 5 valeurs de rôle : ADMIN, IT, RH, GRAPHISTE, FORMATION. Couple unique, plusieurs rôles permis. ADMIN gère. |

## Contrat Excel : onglet Personnel, en-têtes en ligne 1
Le fichier vierge joint a huit colonnes. ID salarié et Matricule sont du texte, pour préserver notamment les zéros initiaux. Pour une nouvelle fiche : Prénom, Nom, Poste, Site et Date d’arrivée sont nécessaires ; pour un import de personnel déjà présent, utiliser la date d’arrivée réelle connue et ne pas créer de parcours. Le site doit correspondre à une valeur du référentiel. Département facultatif ; pas de salaire, pièce RH ni mot de passe dans ce classeur.
- ID applicatif connu → proposer une mise à jour, jamais le remplacement d’identité. À défaut, matricule exact unique → proposer la correspondance. Si les deux identifiants se contredisent, rejeter la ligne. Sans les deux : proposer une création seulement après revue des ressemblances. Aucun rapprochement automatique par le nom seul.
- Une valeur vide dans une mise à jour signifie « conserver » ; effacement volontaire depuis la fiche et tracé. Ignorer les lignes vides. Refuser les formules dans les champs importés ; exporter en texte les identifiants/contenus pouvant ressembler à une formule.
- Avant confirmation : rapport nouvelle/modifiée/à revoir/rejetée et motif, affichage avant/après. Appliquer uniquement la sélection valide en transaction. Une ligne ambiguë n’est jamais appliquée ; après correction, nouveau lot traçable. Export filtré par autorisation ; aucun email déclenché par import.
